# 变更与升级说明

## v1.0.0（2026-11-14）— 首个可交付版本

### 新增

**设备发现**
- UDP 47820 广播发现，3 秒一次探测，12 秒 TTL
- Windows 端逐网卡独立 socket 绑定源地址广播（规避默认选路把包发到 VMware 虚拟网卡的 77% 失败率）
- 双向过滤本机地址与自身 id，避免"发现自己"与"一台设备变三台"

**文件传输**
- 控制连接 NDJSON + 独立数据连接 28 字节二进制帧
- 1 MiB 分块、每连接 8 块滑动窗口、默认 2 条数据连接
- 逐块 CRC32 校验，失败回 NAK 不落盘
- 文件夹递归传输，保留目录结构，空目录显式入清单
- 中文/emoji 文件名全链路 UTF-8，Windows 端路径按 `\\?\` 长路径规则处理
- 接收端路径穿越防护（拒绝 `..`、盘符、NTDS ADS），非法字符与保留名清洗
- 同名文件自动 `(1)` 后缀，不覆盖
- 保留源文件修改时间

**断点续传**
- 任务键 = FNV-1a(peerId + rel + size + mtime + chunkBytes)，与清单顺序无关
- 接收端位图持久化到 `meta.json`，重连时通过 `accept.have` 回传
- 只认位图不认文件长度（末块可能短）

**Windows 端**
- C++17 + Win32 + GDI+ 全自绘暗色界面，单文件 762 KB，零第三方依赖
- 接收列表对齐 Edge 下载模型：临时目录 → 校验 → 移动 → 打开/所在文件夹/**另存为**
- 拖放发送、文件夹拖入、多选
- 系统托盘、单实例、开机自启（默认关）
- 防火墙规则检测与一键修复（自提权）
- 网络类型检测（公用网络提示）
- 资源管理器右键「用内网快传发送」
- 传输历史持久化（`history.ini`）

**Android 端**
- Kotlin + Compose，Material3 暗色
- 「全部文件访问」权限下的真文件管理器体验：面包屑导航、文件夹树、最近文件
- 复选框多选 + 底部「发送到 …」
- 前台服务保活，传输期间 `KEEP_SCREEN_ON` + `PARTIAL_WAKE_LOCK`
- 接收落盘 `Download/LanDrop/`，空目录用文件 API 补齐
- 调试变体提供 `am broadcast` 钩子供自动化驱动

**网速测试**
- 双向/单向、1–8 条并发连接、可配时长
- 每秒采样折线图，输出 avg / peak / p50
- 测速流量不打 ACK，避免反压污染测量

### 交付后修正（同日）
1. **附近设备列表不再跳变**：原排序键为 `lastSeen`（心跳到达时间），两台设备心跳相位错开会让列表
   每 300 ms 重排一次。改为按显示名自然排序（`StrCmpLogicalW`，数字按数值比较），同名以设备 id 兜底；
   `lastSeen` 仅用于 12 秒 TTL 淘汰。实测两台真机同时在线，间隔 5 秒的两帧截图在设备面板区域像素零差异。
2. **防火墙提示更准确**：原来只检查自建规则名 `LanDrop TCP`，用户通过系统弹窗自行放行后仍会误报
   "防火墙未放行"。现在改为「规则未添加」并在**收到任意入站连接后自动消失**——用实际连通性说话。

### 已知问题
见 `docs/交付说明.md` §5。其中第 1 条（熄屏断流）为系统级限制，非缺陷。

### 升级方式
- **Windows**：直接运行新版安装包，会沿用旧安装目录并自动关闭运行中的程序；
  `%APPDATA%\LanDrop` 下的配置与历史保留。卸载时询问是否保留。
- **Android**：直接覆盖安装（同一签名，`versionCode` 递增），数据不丢。
