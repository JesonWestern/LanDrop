# 变更与升级说明

## v1.3.0（2026-11-23）— 文件页体验 · 主题系统 · 页面动画（双端同步）

> 本轮只改**界面层**：协议 v1、UDP 47820 / TCP 47821、断点续传、接收落盘逻辑全部未动。
> e2e 6/6 通过即回归证明。Android `versionCode 3→4`；Windows `1.1.0→1.3.0`（补齐与 Android 的版本号错位）。

### 新增 · Android

**文件页（「文件」tab）重做**
- **顶部左侧页签**：`最近` / `内部存储`。最近文件从 12 条提到 **200 条**（约 10 屏）。
- **最近文件按日期分组**：今天 / 昨天 / `M月d日`（跨年补 `yyyy年M月d日`），段序日期倒序、段内修改时间倒序。
- **三视图可切换并持久化**：列表（60dp + 副标题 + 右侧选择区）/ 紧凑（44dp 无副标题）/ 网格
  （3 列、96dp 缩略图、长按进多选后点每格右上角圆圈）。网格**不做拖选**（二维网格没有 56dp
  选择区那样的防误触缓冲，且跨格命中精度差），多选走长按 + 点圈。
- **拖选可取消**：按下瞬间看锚点行是否已选中 —— 已选中则本次拖动为 `DESELECT`，
  否则 `SELECT`。区间每次从基线重算，拖出去再拖回完全还原，不留半拉残留。
- **全选 / 反选 / 清空 / 退出多选**：发送条常驻。多选态是显式状态（清空后条子不消失），
  否则「清空」等于自断退路 —— 这正是原反馈「缺少全选、取消选中」的成因。
  作用域 = 当前页签的全部可见行；作用域外的旧选中项保留，不悄悄丢掉。
- **切换零等待**：新增 `FileRepo`（目录 8s / 最近 30s TTL 内存缓存 + `MainActivity.onCreate`
  预热）。首帧**同步**读缓存立即出内容，IO 全部推后到后台。实测 4 次切换全部
  `cached=true`（冷启动 626ms，之后 206–250ms），logcat 埋点 `LanDropPerf`。
- 缩略图新增 256px 档（网格用），原 128px 不变；LruCache 上限与 4 路并发保持。

**主题系统**
- **10 个预设**：石墨灰（默认，= 1.2 观感）/ **纯黑**（OLED）/ **纯白** / 银灰 / 深海蓝 /
  松林绿 / 落日橙 / 夜紫 / 玫瑰紫 / 薄荷青。
- **12 色强调色**独立于预设；派生 `accentDim` / `onAccent`（按底色亮度自动选黑或白前景，
  保证浅色主题下不出现「白底白字」）。
- **自定义背景图 + 0–80% 暗化强度**：选图后降采样到 ≤1440px 存应用私有目录
  （不持 `content://`，避免重启/权限回收/原图移动后失效），叠一层可调 scrim 保可读性。
- **集成进设置页**：新增「外观」分组（置顶）——预设色板 5×2、强调色圆点、壁纸选择/清除、
  暗化滑杆、页面切换动画开关，改动**即时生效**（`ThemeStore` 为 `StateFlow`）。
- 冷启动无白闪：`MainActivity` 在 `setContent` 前用持久化主题设 window 背景色。

**页面切换动画**
- 底部 tab、文件页内页签/视图切换均用 `AnimatedContent`：180ms + `FastOutSlowInEasing`，
  按 tab 序号差决定滑入方向，叠 fade，`SizeTransform(clip = false)`；底栏指示条 `animateDpAsState`。
- **退化**：设置里关「页面切换动画」或系统开发者选项把动画时长缩放设为 0，时长即 `tween(0)`
  （Compose 本身也会跟随 `MotionDurationScale`）。
- 兼容：位移用 dp、内容按可用约束裁剪，小高度/横屏窗口不溢出；`rememberSaveableStateHolder`
  仍按 tab 作 key，切回旧页状态不丢。

### 新增 · Windows

- **同一套 10 预设 + 12 强调色**（id 与 Android 严格一致，便于两端对照截图）。
  实现上把 `theme.h` 里 20 个 `constexpr` 颜色改成 `extern uint32_t` 变量 + `Palette g_pal`，
  因此 67 处 `th::cXxx` 调用点零改动；`ApplyTheme()` 写入新值并清空画笔/画刷缓存。
- **标题栏跟随主题**：`ApplyTitleBar()` 按 `g_pal.light` 设 DWM 沉浸式深色/标题栏色/文字色/边框色。
- **壁纸 + 暗化**：`Paint()` 先画壁纸再叠色；壁纸用 DIB + GDI+ cover 缩放并缓存尺寸。
- **切换动画**：内容区离屏快照 → 按 `EaseOutCubic(1-t)` 的 alpha 淡出旧图 + 24dp 横向位移，
  180ms，16ms 计时器；宽 <480dp 只淡入不位移；`WM_SIZE` / DPI 变化 / 再次切 tab 立即取消；
  读 `SPI_GETCLIENTAREAANIMATION` 与设置项双退化。
- **设置页新增「外观」分组（置顶）**：10 预设自绘色块（`BS_OWNERDRAW` + `WM_DRAWITEM`，
  圆角 + bg/accent 双色小样 + 选中描边）、12 强调色圆点 + 「默认」、选择/清除背景图、
  暗化强度 ±（0–80 步进 5）、启用切换动画。高度 600→780 且按屏高 86% 自适应。
- **`--dpi N`**（72–480，仅测试用，不写配置）：用于强制 DPI 做布局/动画兼容性验证。
- `--selftest` 扩展 7 项主题断言（预设数/未知回落/EaseOutCubic/强调色派生/配置夹取等）。

### 修复（本轮发现）

1. **Windows 800×600 布局重叠**：左栏固定 280dp 时右侧不足 300dp，页签与「清除已完成」压字；
   顶栏 IP 与「专用网络」徽标重叠。→ 左栏宽度动态收缩（下限 180dp）；顶栏按余量决定是否画 IP
   （<110dp 整段省略）；「清除已完成」仅在 ≥8dp 间隙时绘制。800×600 与 1280×800 均验证干净。
2. **Windows `swprintf %s` 截断**（既有 bug）：MinGW 下 `%s` 是窄字符语义，设置页
   「本机地址 1」「临时目录 C」「日志 C」被截断；改 `%ls` 后完整。底部状态行同类问题一并修。
3. **Windows 壁纸 alpha**：DIB alpha 全 0 会让 GDI+ 包装后整片消失，置 `0xFF` 修复。
4. **浅色主题可读性**：彩色徽章浅底浅字 → 新增 `TintBg/TintText`；Android 端把
   选中态/主按钮上的硬编码 `Color.White` 统一替换为 `LdColors.OnAccent`。
5. **Android 主题化的编译面**：`LdColors.*` 改为 `@Composable getter` 后，`drawBehind` /
   `DrawScope` 等非组合作用域读取会编译失败，已在 `SelectionGutter`、`SpeedChart`、`kindColor`
   三处改为「组合里先取局部变量」。

### 升级方式

- **Android**：直接覆盖安装（签名与 1.0/1.1/1.2 相同，`versionCode 4`）。
  历史数据（设备 ID、信任列表、传输历史）全部保留；主题默认仍是石墨灰，升级用户观感不变。
- **Windows**：运行 `LanDropSetup-1.3.0.exe` 覆盖安装。`AppId` 与单实例互斥体未变，
  不会变成两个产品；`config.ini` 新增 5 个键（`theme` / `themeAccent` / `themeWallpaper` /
  `themeScrim` / `themeAnimations`），`cfgver` 1→2，旧配置缺键时回落默认（= 原观感）。
- 两端新键均有默认值，**不需要**手动迁移配置。

## v1.0.0（2026-11-14）— 首个可交付版本

### 新增

**设备发现**
- UDP 47820 广播发现，3 秒一次探测，12 秒 TTL
- Windows 端逐网卡独立 socket 绑定源地址广播（规避默认选路把包发到 VMware 虚拟网卡的 77% 失败率）
- 双向过滤本机地址与自身 id，避免"发现自己"与"一台设备变三台"

**文件传输**
- 控制连接 NDJSON + 独立数据连接 28 字节二进制帧
- 1 MiB 分块、每连接 8 块滑动窗口、默认 2 条数据连接
- 逐块 CRC32 校验，失败回 NAK 不落盘
- 文件夹递归传输，保留目录结构，空目录显式入清单
- 中文/emoji 文件名全链路 UTF-8，Windows 端路径按 `\\?\` 长路径规则处理
- 接收端路径穿越防护（拒绝 `..`、盘符、NTDS ADS），非法字符与保留名清洗
- 同名文件自动 `(1)` 后缀，不覆盖
- 保留源文件修改时间

**断点续传**
- 任务键 = FNV-1a(peerId + rel + size + mtime + chunkBytes)，与清单顺序无关
- 接收端位图持久化到 `meta.json`，重连时通过 `accept.have` 回传
- 只认位图不认文件长度（末块可能短）

**Windows 端**
- C++17 + Win32 + GDI+ 全自绘暗色界面，单文件 762 KB，零第三方依赖
- 接收列表对齐 Edge 下载模型：临时目录 → 校验 → 移动 → 打开/所在文件夹/**另存为**
- 拖放发送、文件夹拖入、多选
- 系统托盘、单实例、开机自启（默认关）
- 防火墙规则检测与一键修复（自提权）
- 网络类型检测（公用网络提示）
- 资源管理器右键「用内网快传发送」
- 传输历史持久化（`history.ini`）

**Android 端**
- Kotlin + Compose，Material3 暗色
- 「全部文件访问」权限下的真文件管理器体验：面包屑导航、文件夹树、最近文件
- 复选框多选 + 底部「发送到 …」
- 前台服务保活，传输期间 `KEEP_SCREEN_ON` + `PARTIAL_WAKE_LOCK`
- 接收落盘 `Download/LanDrop/`，空目录用文件 API 补齐
- 调试变体提供 `am broadcast` 钩子供自动化驱动

**网速测试**
- 双向/单向、1–8 条并发连接、可配时长
- 每秒采样折线图，输出 avg / peak / p50
- 测速流量不打 ACK，避免反压污染测量

### 交付后修正（同日）
1. **附近设备列表不再跳变**：原排序键为 `lastSeen`（心跳到达时间），两台设备心跳相位错开会让列表
   每 300 ms 重排一次。改为按显示名自然排序（`StrCmpLogicalW`，数字按数值比较），同名以设备 id 兜底；
   `lastSeen` 仅用于 12 秒 TTL 淘汰。实测两台真机同时在线，间隔 5 秒的两帧截图在设备面板区域像素零差异。
2. **防火墙提示更准确**：原来只检查自建规则名 `LanDrop TCP`，用户通过系统弹窗自行放行后仍会误报
   "防火墙未放行"。现在改为「规则未添加」并在**收到任意入站连接后自动消失**——用实际连通性说话。

### 已知问题
见 `docs/交付说明.md` §5。其中第 1 条（熄屏断流）为系统级限制，非缺陷。

### 升级方式
- **Windows**：直接运行新版安装包，会沿用旧安装目录并自动关闭运行中的程序；
  `%APPDATA%\LanDrop` 下的配置与历史保留。卸载时询问是否保留。
- **Android**：直接覆盖安装（同一签名，`versionCode` 递增），数据不丢。

## v1.1.0（2026-11-19）— Windows 端按钮修复 + Android 端体验与传输优化

> Windows 端首次升到 1.1.0（修接收列表按钮点击无响应）；Android 端沿用 11-14 的 1.1.0 构建。
> 协议仍为 `v1`，两端可任意混用，新旧版本互通。

### 新增：按类型区分的文件图标

- 新增 `FileKind`：图片 / 视频 / 音频 / 文档 / 压缩包 / 安装包 / 其它。判定以扩展名优先
  （约 120 项映射），扩展名未命中时按 MIME 前缀兜底 —— 很多 provider 只会给
  `application/octet-stream`，只看 MIME 会全部落进「其它」。
- `FileGlyph` 从「文件夹 + 文档」两种形状扩展为 7 种手绘剪影：相框+山峦、播放三角、
  音符、折角纸、拉链箱、下箭头、单页。零新增依赖（本地 Gradle 缓存无 material-icons）。
- 颜色仅作辅助（图片绿/视频紫/音频橙/文档蓝/压缩包黄/安装包青），灰度下靠剪影区分。

### 新增：「分类」页（底部第 5 个标签）

- 一级：7 类卡片宫格，显示每类的数量与总大小；二级：该类全部文件，支持
  名称（拼音序）/ 大小 / 时间 / 类型 四种排序，再点同一项翻转升降序；可多选发送。
- 数据源可切换：
  - **媒体库索引**（默认）：`MediaStore.Files` 查询，带 `QUERY_ARG_LIMIT 20000`，
    60 秒内存缓存 + `ContentObserver` 失效，避免每次进页重扫、避免大库拉全表 ANR。
  - **全盘深度扫描**：迭代式 DFS，整棵剪掉 `Android/`，跳过隐藏目录与 `.nomedia` 目录，
    单线程限流（每 500 个文件让出），结果写二进制缓存（10 万条约 7 MB / 200 ms），24 小时有效。

### 新增：系统分享 / 打开方式入口

- 注册 `ACTION_SEND`、`ACTION_SEND_MULTIPLE`、`ACTION_VIEW`，均为 `*/*`。
  在相册、文件管理器等位置「分享」或「打开方式」里都能看到内网快传。
- 跳转后弹窗列出在线设备，**默认全选、可多选**，确认后每台设备各自建立一个任务
  （跨设备并发上限 2，单设备串行）。
- `content://` 支持三级降级：可解析真实路径 → `ParcelFileDescriptor` 定位读（零拷贝，
  4 GB 视频不占额外磁盘）→ 复制到 cacheDir（仅管道型来源）。
- `MainActivity` 改为 `singleTop` 并实现 `onNewIntent`，应用在后台时再次分享可正常响应。

### 优化：手机 ↔ 手机传输

| 方向 | 改动 |
|---|---|
| 速度 | 发送端每 worker 复用文件句柄（LRU 8）——Android 的 `/sdcard` 是 FUSE，原来每 1 MiB open/close 一次是最大热点；帧头与载荷合并成一次 `write`；默认并发连接 2 → 3 |
| 稳定性 | 修「确认超时倒挂」（接收端等 60 秒人工确认，发送端原来 30 秒就放弃）；换 WiFi 后重建广播 socket（原来会「别人能发现我，我发现不了别人」）；传输期间持有 WifiLock；设备/任务列表去抖，不再每 400 ms 全页重组 |
| 恢复 | 发送失败自动重试 3 次（退避 800 ms×n）；接收端每 3 秒周期落盘位图、`meta.json` 原子写；落盘预分配文件大小；启动清理 7 天前或超 2 GB 的接收残留；传输页提供「重试」 |

### 修复

1. **任务号撞号**：发送任务从 2、接收任务从 100 各自自增，发送到第 99 个任务时必然与某个
   接收任务同号，导致 `cancel(id)` 取消错任务、任务列表 `LazyColumn` 重复 key 崩溃。
   现统一由 `JobIds` 发号。
2. **MIME 判定顺序**：`application/vnd.android.package-archive` 含 "archive"，曾被误判成压缩包。
3. **文件页统计**：根目录下「最近文件」与当前目录条目重叠，已选大小被重复累加。
4. **分区标题**：「文件夹」标题下原先把文件也混排进去，现拆成「文件夹」「文件」两段。
5. **无设备提示**：点「未发现设备」原先跳到测速页（笔误），现在跳设置页。
6. **测速握手的版本号**：`Speed.kt` 里 `ver` 写死 `"1.0.0"`，与 `versionName` 不一致，
   改成读 `BuildConfig.VERSION_NAME`（设备发现与发送握手本来就是读它）。

### 修复（Windows）：接收列表「打开 / 所在文件夹 / 另存为」点了没反应

- **根因**：命中矩形（hit）注册顺序反了。`FindHit()` 后注册优先，而 `DownloadRow()` 先注册三个
  按钮、最后才注册整行，整行矩形盖住按钮区域且优先级更高，点击永远落在 `HK_RecvRow` 上，
  而 `OnClick` 没有该分支 → 静默无响应。连带症状：按钮悬停也不高亮。发送列表的「取消」同理。
- **修法**：行命中改为在绘制背景前注册（按钮后注册即优先）；行与按钮的命中区统一裁剪到列表
  可视区域，避免滚动后被卷上去的行矩形溢出压住页签/顶栏。
- 顺带加固：`savePath` 为空时回退 `saveDir`；路径已不存在时明确弹窗提示（原为静默失败）；
  「打开」检查 `ShellExecuteW` 返回值，「所在文件夹」对目录直接打开、对文件才 `explorer /select,`。
- 版本号：`1.0.0` → `1.1.0`（exe 资源、安装包、关于对话框统一）。

### 兼容性

- 协议保持 `v1`：帧头 28 字节、1 MiB 块大小、`taskId` 派生方式、逐块 ACK 全部未动。
- 发送端窗口、帧头与载荷合并写、连接时序都是纯本地行为，Windows 端不感知。
- `versionCode` 1 → 2，`versionName` 1.0.0 → 1.1.0，签名不变，可直接覆盖安装。
- Windows：`FileVersion`/`ProductVersion` 1.0.0.0 → 1.1.0.0，安装包 `AppId` 与单实例互斥体
  （`LanDropSingleInstance_v1`）均未改动，v1.0.0 覆盖升级后设置与传输历史原样保留。

### 升级方式

- **Windows**：用 `LanDropSetup-1.1.0.exe` 覆盖安装，`%APPDATA%\LanDrop` 下的配置与历史保留。
- **Android**：覆盖安装即可（同一签名），`deviceId` 与信任列表保留；分类页默认仍走媒体库索引，
  行为与 1.0.0 一致。

## v1.2.0（2026-11-22）— Android 文件浏览体验与数据正确性

> 协议仍为 `v1`，Windows 端未改动；Android `versionCode` 2 → 3，`versionName` 1.1.0 → 1.2.0，
> 签名不变，可直接覆盖安装。

### 新增：文件列表缩略图

- 图片行显示 40dp 缩略图：媒体库来源优先 `ContentResolver.loadThumbnail`（系统处理 EXIF/HEIC/尺寸），

### 修复：分类页文件数量不可信（尤其图片）

本机实测：同一时刻旧实现图片卡片 **105**，系统相册 `images/media` 与磁盘可见文件均 **92**；
差额 = 5 张隐藏父目录里的图片 + 8 条 MediaStore 失联行。分桶共 4 处原因，全部修复：

1. **目录行被当文件**：`MediaStore.Files` 会返回目录（本机 mime 为空的行 390 条，经 `find`/`ls -ld`
   交叉验证全部是目录；策略实际剔除 356 条，其余 34 条先被点文件名/隐藏路径过滤）。
   现在对 mime 为空的行用文件系统判定并剔除。
2. **失联行**：MediaStore 里已删除的文件仍残留（本机 8 条图片）。现在按 `_data` 校验存在性后剔除。
3. **隐藏父目录**：旧实现只看文件名是否点开头，`Pictures/.gs/.../a.jpg` 这类仍被计入（本机 43 行、
   含 5 张图片）。新增 `CatalogPolicy.isVisiblePath`：分类页、最近文件、全盘扫描共用；
   文件页列表仍只跳过点开头条目。
4. **排序参数类型错误 + 静默截断**：`QUERY_ARG_SQL_SORT_ORDER` 契约类型是 `String`，旧代码传
   `StringArray`，provider 静默忽略排序；配合 `LIMIT 20000`，超大库会取到**最旧**的 2 万行。
   已改为 `putString`；请求 `LIMIT+1` 行并在内存侧兜底截断（旧 MediaProvider 不认 LIMIT），
   `truncated = 行数 > LIMIT`，恰好 2 万条不再误报。
5. 附带：按 `_data` 去重（本机 0 条重复，防御性）；分桶计数与列表同源；分类详情排序移到
   `Dispatchers.Default`（20 万条不再 ANR）；全盘扫描开关在扫描期间保持 ON（旧实现会弹回 OFF）；
   媒体库 60s 缓存改为 15s，并在接收完成后主动失效，同时观察 Images/Video/Audio/Downloads。

> 最终构建实测：查询行 5919 → 条目 5402（图片 92 / 文档 2985 / 压缩包 6 / 安装包 1 / 其它 2318），
> 剔除 517 = 356 目录行 + 118 点文件名 + 43 隐藏父目录（失联与重复均为 0）。
> 此前 23:16 的快照 raw=5927 / dropped=525，其中额外 8 条为后被系统清理的失联行。

### 新增：传输页按文件明细与打开

- 任务卡可展开文件列表：名称、大小、单文件进度/完成标记；收到的文件行带缩略图并有「打开」，
  发送任务的本地文件同样可打开；单文件任务在任务卡直接提供「打开」。

### 复审补丁（2026-11-23，第二轮独立只读复核后）

- **P1 跨目录同名文件 rel 冲突**：不同目录下的同名文件在清单里 rel 相同，接收端两条位图流写同一个
  `.part` 互相覆盖（静默数据损坏）。发送端现按 rel 自动消歧（`same (1).txt`），接收端对重复 rel
  直接拒绝（兼容旧版发送端），不再写坏。
- `publishQ` 忽略 `resolver.update(IS_PENDING=0)` 返回值 → 可能判成功但文件仍不可见；现校验并回滚。
  legacy 分支补字节数校验与半截文件清理。
- API 29 上“空目录创建失败”原会把整单判 FAILED（文件其实已发布）；现降级为 warning（任务 DONE）。
- 接收任务完成/失败后统一 `closeSession`，避免控制 socket CLOSE_WAIT 泄漏。
- 发送端按接收端 `error.reason/detail` 显示“对方保存失败：…”，不再一律“校验失败”。
- 分类查询请求 `LIMIT+1`、内存侧兜底并 `truncated = 行数 > LIMIT`；全盘扫描复用同一可见性口径
  （缓存版本升 2）；`warm()` 的缓存解析移到 IO 线程；`refresh` 代号改 `AtomicInteger`（网络线程可安全 invalidate）。
- FileProvider 去掉 `root-path`（最小授权）；系统选择器识别扩展到 `com.android.intentresolver` 等；
  设置页冷启动显示“正在读取索引…”，不再短暂显示 0。
- 最终回归：单测 **37/37**、e2e **6/6**、`check_apk.ps1` 全 PASS（日志见 `docs/verify/*-1.2.0.log`）。
