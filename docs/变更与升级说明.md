# 变更与升级说明

## v1.0.0（2026-11-14）— 首个可交付版本

### 新增

**设备发现**
- UDP 47820 广播发现，3 秒一次探测，12 秒 TTL
- Windows 端逐网卡独立 socket 绑定源地址广播（规避默认选路把包发到 VMware 虚拟网卡的 77% 失败率）
- 双向过滤本机地址与自身 id，避免"发现自己"与"一台设备变三台"

**文件传输**
- 控制连接 NDJSON + 独立数据连接 28 字节二进制帧
- 1 MiB 分块、每连接 8 块滑动窗口、默认 2 条数据连接
- 逐块 CRC32 校验，失败回 NAK 不落盘
- 文件夹递归传输，保留目录结构，空目录显式入清单
- 中文/emoji 文件名全链路 UTF-8，Windows 端路径按 `\\?\` 长路径规则处理
- 接收端路径穿越防护（拒绝 `..`、盘符、NTDS ADS），非法字符与保留名清洗
- 同名文件自动 `(1)` 后缀，不覆盖
- 保留源文件修改时间

**断点续传**
- 任务键 = FNV-1a(peerId + rel + size + mtime + chunkBytes)，与清单顺序无关
- 接收端位图持久化到 `meta.json`，重连时通过 `accept.have` 回传
- 只认位图不认文件长度（末块可能短）

**Windows 端**
- C++17 + Win32 + GDI+ 全自绘暗色界面，单文件 762 KB，零第三方依赖
- 接收列表对齐 Edge 下载模型：临时目录 → 校验 → 移动 → 打开/所在文件夹/**另存为**
- 拖放发送、文件夹拖入、多选
- 系统托盘、单实例、开机自启（默认关）
- 防火墙规则检测与一键修复（自提权）
- 网络类型检测（公用网络提示）
- 资源管理器右键「用内网快传发送」
- 传输历史持久化（`history.ini`）

**Android 端**
- Kotlin + Compose，Material3 暗色
- 「全部文件访问」权限下的真文件管理器体验：面包屑导航、文件夹树、最近文件
- 复选框多选 + 底部「发送到 …」
- 前台服务保活，传输期间 `KEEP_SCREEN_ON` + `PARTIAL_WAKE_LOCK`
- 接收落盘 `Download/LanDrop/`，空目录用文件 API 补齐
- 调试变体提供 `am broadcast` 钩子供自动化驱动

**网速测试**
- 双向/单向、1–8 条并发连接、可配时长
- 每秒采样折线图，输出 avg / peak / p50
- 测速流量不打 ACK，避免反压污染测量

### 交付后修正（同日）
1. **附近设备列表不再跳变**：原排序键为 `lastSeen`（心跳到达时间），两台设备心跳相位错开会让列表
   每 300 ms 重排一次。改为按显示名自然排序（`StrCmpLogicalW`，数字按数值比较），同名以设备 id 兜底；
   `lastSeen` 仅用于 12 秒 TTL 淘汰。实测两台真机同时在线，间隔 5 秒的两帧截图在设备面板区域像素零差异。
2. **防火墙提示更准确**：原来只检查自建规则名 `LanDrop TCP`，用户通过系统弹窗自行放行后仍会误报
   "防火墙未放行"。现在改为「规则未添加」并在**收到任意入站连接后自动消失**——用实际连通性说话。

### 已知问题
见 `docs/交付说明.md` §5。其中第 1 条（熄屏断流）为系统级限制，非缺陷。

### 升级方式
- **Windows**：直接运行新版安装包，会沿用旧安装目录并自动关闭运行中的程序；
  `%APPDATA%\LanDrop` 下的配置与历史保留。卸载时询问是否保留。
- **Android**：直接覆盖安装（同一签名，`versionCode` 递增），数据不丢。

## v1.1.0（2026-11-14）— Android 端体验与传输优化

> Windows 端二进制未改动，与 v1.0.0 完全兼容（协议仍为 `v1`）。

### 新增：按类型区分的文件图标

- 新增 `FileKind`：图片 / 视频 / 音频 / 文档 / 压缩包 / 安装包 / 其它。判定以扩展名优先
  （约 120 项映射），扩展名未命中时按 MIME 前缀兜底 —— 很多 provider 只会给
  `application/octet-stream`，只看 MIME 会全部落进「其它」。
- `FileGlyph` 从「文件夹 + 文档」两种形状扩展为 7 种手绘剪影：相框+山峦、播放三角、
  音符、折角纸、拉链箱、下箭头、单页。零新增依赖（本地 Gradle 缓存无 material-icons）。
- 颜色仅作辅助（图片绿/视频紫/音频橙/文档蓝/压缩包黄/安装包青），灰度下靠剪影区分。

### 新增：「分类」页（底部第 5 个标签）

- 一级：7 类卡片宫格，显示每类的数量与总大小；二级：该类全部文件，支持
  名称（拼音序）/ 大小 / 时间 / 类型 四种排序，再点同一项翻转升降序；可多选发送。
- 数据源可切换：
  - **媒体库索引**（默认）：`MediaStore.Files` 查询，带 `QUERY_ARG_LIMIT 20000`，
    60 秒内存缓存 + `ContentObserver` 失效，避免每次进页重扫、避免大库拉全表 ANR。
  - **全盘深度扫描**：迭代式 DFS，整棵剪掉 `Android/`，跳过隐藏目录与 `.nomedia` 目录，
    单线程限流（每 500 个文件让出），结果写二进制缓存（10 万条约 7 MB / 200 ms），24 小时有效。

### 新增：系统分享 / 打开方式入口

- 注册 `ACTION_SEND`、`ACTION_SEND_MULTIPLE`、`ACTION_VIEW`，均为 `*/*`。
  在相册、文件管理器等位置「分享」或「打开方式」里都能看到内网快传。
- 跳转后弹窗列出在线设备，**默认全选、可多选**，确认后每台设备各自建立一个任务
  （跨设备并发上限 2，单设备串行）。
- `content://` 支持三级降级：可解析真实路径 → `ParcelFileDescriptor` 定位读（零拷贝，
  4 GB 视频不占额外磁盘）→ 复制到 cacheDir（仅管道型来源）。
- `MainActivity` 改为 `singleTop` 并实现 `onNewIntent`，应用在后台时再次分享可正常响应。

### 优化：手机 ↔ 手机传输

| 方向 | 改动 |
|---|---|
| 速度 | 发送端每 worker 复用文件句柄（LRU 8）——Android 的 `/sdcard` 是 FUSE，原来每 1 MiB open/close 一次是最大热点；帧头与载荷合并成一次 `write`；默认并发连接 2 → 3 |
| 稳定性 | 修「确认超时倒挂」（接收端等 60 秒人工确认，发送端原来 30 秒就放弃）；换 WiFi 后重建广播 socket（原来会「别人能发现我，我发现不了别人」）；传输期间持有 WifiLock；设备/任务列表去抖，不再每 400 ms 全页重组 |
| 恢复 | 发送失败自动重试 3 次（退避 800 ms×n）；接收端每 3 秒周期落盘位图、`meta.json` 原子写；落盘预分配文件大小；启动清理 7 天前或超 2 GB 的接收残留；传输页提供「重试」 |

### 修复

1. **任务号撞号**：发送任务从 2、接收任务从 100 各自自增，发送到第 99 个任务时必然与某个
   接收任务同号，导致 `cancel(id)` 取消错任务、任务列表 `LazyColumn` 重复 key 崩溃。
   现统一由 `JobIds` 发号。
2. **MIME 判定顺序**：`application/vnd.android.package-archive` 含 "archive"，曾被误判成压缩包。
3. **文件页统计**：根目录下「最近文件」与当前目录条目重叠，已选大小被重复累加。
4. **分区标题**：「文件夹」标题下原先把文件也混排进去，现拆成「文件夹」「文件」两段。
5. **无设备提示**：点「未发现设备」原先跳到测速页（笔误），现在跳设置页。

### 兼容性

- 协议保持 `v1`：帧头 28 字节、1 MiB 块大小、`taskId` 派生方式、逐块 ACK 全部未动。
- 发送端窗口、帧头与载荷合并写、连接时序都是纯本地行为，Windows 端不感知。
- `versionCode` 1 → 2，`versionName` 1.0.0 → 1.1.0，签名不变，可直接覆盖安装。

### 升级方式

- **Windows**：无需升级。
- **Android**：覆盖安装即可（同一签名），`deviceId` 与信任列表保留；分类页默认仍走媒体库索引，
  行为与 1.0.0 一致。
