### 4.3 两轮审查发现并修复的关键缺陷

**第一轮（4 路只读审查，11-22）**

1. **分类计数虚高**：MediaStore 目录行（实测 390 行 mime 为空、全部为目录；策略剔除 356 行）、
   已删除的失联行（8 条图片）、隐藏父目录内文件（43 行、含 5 张图片）、重复路径（本机 0，防御性去重）
   被计入分类。旧实现图片 105 = 真实可见 92 + 5 隐藏父目录 + 8 失联。
2. **排序参数类型错误**：`QUERY_ARG_SQL_SORT_ORDER` 契约类型是 `String`，旧代码传 `String[]`，
   被 MediaProvider 静默忽略；配合 `LIMIT 20000`，超大库会取到**最旧**的 2 万行且无提示。
3. **接收失败静默丢文件**：`DownloadSink.publish()` 失败仍返回展示路径，`ReceiverServer` 判 DONE
   并删除唯一副本。1.2 改为结构化 `Published(ok/err/uri/absPath)`，失败保留临时目录、任务标 FAILED。
4. **API 26-29 崩溃**：`Environment.isExternalStorageManager()`（30+）在默认「文件」页启动即调用；
   `MediaStore.Downloads`（29+）在旧系统接收提交必失败。已加 SDK 分支与运行时权限。
5. **发送侧逐文件进度低报**：应用接收端 `have` 位图后未 `recount()`。
6. 其他：同名接收文件被 MediaProvider 改名后记录路径不符（现回查真实名）、选中父目录又选子文件产生
   重复清单项、发送遍历在主线程造成大目录卡顿、Debug 广播入口被编进 release（已移到 debug 源集）。

**第二轮（3 路独立只读复核，11-23）**

7. **跨目录同名文件 rel 冲突**（P1，静默数据损坏）：不同目录下同名文件在发送清单里 rel 相同，
   接收端两条位图流写同一个 `.part` 互相覆盖。发送端现在按 rel 自动消歧（`same (1).txt`），
   接收端对重复 rel 直接拒绝（旧版发送端），不再写坏。
8. `publishQ` 忽略 `resolver.update(IS_PENDING=0)` 返回值 → 可能判定成功但文件仍 pending；
   现校验并失败回滚。legacy 分支补字节校验与半截文件清理。
9. API 29 上“空目录创建失败”会把整单判 FAILED（文件其实已发布）；现降级为 warning。
10. 接收任务完成后控制 socket 未关闭（CLOSE_WAIT FD 泄漏）；现统一 `closeSession`。
11. 发送端把接收端 `error.detail` 一律显示为“对方校验失败”；现按 reason 显示“对方保存失败：…”。
12. 旧 MediaProvider 不认 `QUERY_ARG_LIMIT`：改为请求 `LIMIT+1` 并只读 20001 行，内存侧兜底截断，
    `truncated` 用 `>LIMIT` 判定（恰好 2 万不再误报）。
13. 全盘扫描改为复用 `CatalogPolicy.isVisiblePath`（缓存版本升 2）；FileProvider 去掉 `root-path`
   （最小授权）；系统选择器识别扩展到 `com.android.intentresolver` 等；设置页冷启动显示“正在读取索引…”。

## 5. 已知限制（必读）

| # | 限制 | 原因 | 影响与对策 |
|---|---|---|---|
| 1 | 手机熄屏后无法被电脑发现 | 熄屏后 WiFi 固件在 PSM 状态丢弃广播，应用层无解 | 手机保持亮屏；传输期间自动 `KEEP_SCREEN_ON` |
| 2 | Windows「公用网络」无法自动切换 | 需管理员且可能被组策略锁定 | 顶栏橙色胶囊提示 + 一键跳系统设置 |
| 3 | 无加密 | 首版取舍（明文 + 接收确认 + 信任库） | 协议预留 `v`/`caps`，后续可加 TLS |
| 4 | Android 空目录依赖全部文件访问 | MediaStore 无法表达空目录 | 用文件 API 直接创建；失败降级为 warning（不判整单失败） |
| 5 | 同名文件不会覆盖 | 两端都生成 `(1)` 后缀 | 刻意设计，避免误删 |
| 6 | 单任务并发连接默认 2 | 手机端落盘随机写较弱 | 设置页可调到 4 |
| 7 | 无自动更新 | 首版未做 | 覆盖安装即可升级 |
| 8 | 跨网段/跨公网不可用 | 仅广播发现 | 协议已支持 IP 直连，UI 未做 |
| 9 | 分类计数口径 = 系统媒体库索引 | MediaStore 与文件管理器口径天然不同；不含隐藏父目录/`.nomedia` 目录 | 页面标注数据源；需要全盘真实数时开「全盘深度扫描」 |
| 10 | 单次索引最多 2 万条 | 控制 Cursor/内存上限（Q+ 由 provider 截断，旧系统在内存侧兜底） | 达到上限时页面显示“仅统计最近 2 万条索引” |
| 11 | 拖选不支持边缘自动滚动 | v1 取舍 | 先正常滚动到目标区域再拖选 |
| 12 | 视频/音频不做缩略图 | 逐行抽帧成本高 | 保持手绘图标（本期需求只要求图片与 APK） |
| 13 | API<28 的 HEIC 无法解码缩略图 | `BitmapFactory` 对 HEIF 从 API 28 起支持 | 回退手绘图标，不影响打开 |
| 14 | 点 APK 需要「安装未知应用」授权 | 系统安全策略 | 未授权时跳系统设置页，返回后再点一次 |
| 15 | **仅 Android 12 真机回归** | 本轮只有 API 31 设备；APK targetSdk 36 | Android 13-16 的通知权限、前台服务超时、边到边/预测性返回**未实测**；上线前建议补 AVD 冒烟 |
| 16 | Android 8-10（API 26-29）未真机回归 | 同上 | 代码已加 SDK 分支与旧版落盘路径，但无对应单测/真机 |
| 17 | 单次清单 >1 万文件可能失败 | 控制连接单行 JSON 上限 1 MiB | 本期未改协议；超大目录建议分批发送 |
| 18 | 设置/分类页冷启动可能短暂显示“统计中/正在读取索引” | 媒体库查询 + 存在性校验在 IO 线程异步完成 | 已显示加载态；15 秒 TTL 内不重复查询 |

## 7. 后续建议（按性价比排序）

1. **二维码/手动 IP 兜底**：AP 隔离的酒店/公司网络下广播不可用。
2. **前台服务通知带进度 + Android 15 `Service.onTimeout`**：长时间监听避免被系统判定超时。
3. **TLS 1.3 + 配对码**：协议已留位。
4. **分类页：媒体库/全盘扫描口径统一 + 增量刷新 + 按目录筛选**。
5. **拖选边缘自动滚动、长按进入多选**。
6. **大清单传输**：`offer` 分批或提升单行上限（>1 万文件）。
7. **API 26-29 与 Android 13-16 AVD 回归**：补浏览器/接收/打开/权限的跨版本冒烟。
